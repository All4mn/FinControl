Relatório Individual — 2º Bimestre

Nome: Allan Guilherme Camargo de Oliveira

Projeto: FinControl

Disciplina: Projeto Integrador
1. Atividades realizadas

Durante este bimestre, atuei de forma estratégica na liderança e gestão do fluxo de trabalho do projeto FinControl, concentrando meus esforços na governança do repositório, gerenciamento de tarefas e garantia de qualidade do ciclo de desenvolvimento. As atividades realizadas incluem:

    Gestão de Fluxo no GitHub Projects: Organização, triagem e monitoramento do progresso das tarefas da equipe utilizando a ferramenta GitHub Projects, assegurando o cumprimento dos prazos e a transparência das entregas.

    Revisão de Commits e Code Review: Supervisão e revisão contínua dos commits submetidos pela equipe para garantir a integridade do código e o alinhamento com as boas práticas de desenvolvimento estabelecidas para o projeto.

    Estruturação de Branches Estratégicas: Criação e gerenciamento de branches fundamentais para o fluxo de trabalho (Git Flow), como a development (ambiente de integração e testes das novas funcionalidades) e a documents (centralização de relatórios e artefatos de documentação).

    Padronização das Estruturas de Features: Definição e aplicação de padrões rigorosos na nomenclatura, escopo e arquitetura das novas ramificações (feature branches), facilitando o processo de integração e evitando conflitos no repositório.

2. Conhecimentos adquiridos

Este trabalho permitiu consolidar e aprofundar conhecimentos práticos em:

    Governança de Repositórios e Git Flow: Domínio sobre estratégias avançadas de ramificação e integração contínua, organizando o ciclo de vida do software de forma profissional.

    Gestão Ágil de Projetos: Utilização prática do GitHub Projects para a distribuição de demandas, priorização de tarefas e acompanhamento de métricas de produtividade do time.

    Garantia de Qualidade (QA): Análise crítica de código de terceiros através de revisões de commits, identificando precocemente possíveis quebras de padrão ou conflitos de mesclagem.

    Padronização Arquitetural: Compreensão da importância de estabelecer uma taxonomia clara para branches e commits, o que reduz drasticamente o tempo gasto em integrações (merges).

3. Principais dificuldades encontradas

As maiores dificuldades técnicas e de gestão enfrentadas ao longo do período foram:

    Sincronização do Fluxo de Trabalho: Alinhar o ritmo de desenvolvimento da equipe para que todos seguissem estritamente o padrão de criação de branches e submissão de commits nas ramificações corretas.

    Resolução de Conflitos na Integração: Gerenciar e mitigar conflitos complexos de código (merge conflicts) na branch development devido ao desenvolvimento simultâneo de diferentes features pelos membros do time.

    Manutenção do Quadro de Tarefas Atualizado: Garantir que o status das atividades no GitHub Projects refletisse fielmente o progresso real do desenvolvimento em tempo real.

4. Como superei as dificuldades

Para superar esses desafios de forma eficiente, adotei as seguintes estratégias:

    Alinhamento e Cultura de Padronização: Estabelecimentos de diretrizes claras de Git para a equipe, definindo prefixos e regras de nomenclatura para as features antes do início do desenvolvimento.

    Revisões de Código Defensivas: Implementação de rotinas de revisão mais frequentes e detalhadas antes de aprovar a integração de novos códigos na branch development, isolando falhas antes que chegassem ao ambiente compartilhado.

    Automação e Vínculo com Pull Requests: Utilização de recursos do GitHub para vincular diretamente os Pull Requests aos cartões do GitHub Projects, automatizando a movimentação das tarefas e reduzindo o trabalho manual de atualização.

5. Contribuição para o projeto

Minha atuação trouxe impactos diretos e significativos na organização e na maturidade técnica do desenvolvimento do FinControl:

    Repositório Organizado e Seguro: A criação das branches development e documents isolou o código estável, organizou a documentação e eliminou o risco de alterações diretas e acidentais na branch principal.

    Rastreabilidade e Transparência: Através do gerenciamento no GitHub Projects, a equipe e os stakeholders ganharam total visibilidade sobre o status real de cada funcionalidade do sistema.

    Redução de Dívida Técnica: A revisão constante de commits e a padronização das estruturas de features garantiram um histórico de Git limpo, facilitando futuras auditorias de código e manutenções do software.

6. Considerações finais

Este bimestre foi fundamental para consolidar minhas habilidades em liderança técnica e gerenciamento de configuração de software. Garantir que a infraestrutura de desenvolvimento do FinControl funcionasse de maneira coordenada permitiu que a equipe programasse com mais segurança e previsibilidade.

Os próximos passos focarão no refinamento do pipeline de integração do projeto, garantindo que as próximas features implementadas sigam o mesmo rigor técnico e fluam sem gargalos até as entregas finais.
